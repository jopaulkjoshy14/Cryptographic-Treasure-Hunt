About the project

Security meets adventure

Cryptographic Treasure Hunt combines a traditional treasure hunt with browser-based encryption, allowing participants to discover and unlock clues through a secure cryptographic workflow.

Discover. Decrypt. Advance.
Project overview

How Cryptographic Treasure Hunt works

The system separates the encrypted message from the key, making the hunt more interactive and challenging.

1

Organizer creates a clue

The organizer enters a secret message and a secret key into the organizer portal.

2

The clue is encrypted

AES-256-GCM encrypts the message directly inside the organizer’s browser.

3

Both parts are distributed

The ciphertext and secret key can be shared separately using text or QR codes.

4

Participant reveals the clue

After discovering both values, the participant decrypts the message in the participant portal.

Security principles

Designed for local processing

The application focuses on keeping the cryptographic workflow inside the user’s browser.

Client-side encryption

The secret message is encrypted within the browser before the resulting ciphertext is distributed.

AES-256-GCM

AES-256-GCM provides authenticated encryption, helping protect the confidentiality and integrity of the clue.

No server storage

The application does not require a server to store the plaintext message or secret key.

QR-enabled discovery

Ciphertext and keys can be represented as QR codes for convenient physical or digital clue placement.

Technology
